# SIH26047 — Patient Case-Taking Software (MediKiosk)

**Organization:** All India Institute of Ayurveda, Ministry of Ayush  
**Category:** Software · **Theme:** Medtech / Biotech / Healthtech  
**Deadline:** 20 September 2026

## Description — Background

### 1.1 Clinical history-taking bottleneck

History taking is the single most important diagnostic activity in clinical medicine (70–80% of diagnoses from history alone). Indian OPDs see 4,000–10,000 patients/day with 2–5 minute consult windows. AYUSH Dashavidha Pariksha requires even deeper assessment than allopathic intake.

### 1.2 Records fragmentation

Patients carry unstructured paper records. ABDM solved interoperability but not the first-mile intake problem.

### 1.3 Opportunity

Self-service kiosks + Indian ASR + LLMs + OCR + ABDM FHIR make AI-powered clinical intake feasible.

## Description

No patient-facing platform exists for voice/touch history + document digitization + physician-ready summary before consultation.

## Expected Solution — MediKiosk

| Module | Capability |
|--------|------------|
| A | Conversational multimodal history (SOCRATES, AYUSH mode, red flags) |
| B | Document OCR, extraction, timeline |
| C | Structured physician summary |
| D | DPDP + ABDM consent and FHIR push |

**Journey:** Identify → Converse → Scan → Summarize & Route → Consult
